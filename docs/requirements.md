## 产品目标

目标用户：需要整理并迁移电脑中分散文件的人；当前需求来自用户本人的文件迁移经历。

核心问题：待迁移文件散落在不同文件夹，逐一整理后再打包传输的过程繁琐。

产品目标：支持跨文件夹持续收集文件，并统一打包，减少迁移前反复整理文件的操作。

## 核心使用流程

1. 用户在电脑上浏览某个文件夹，选中需要迁移的一个或多个文件、文件夹，也可混合选择。
2. 将选中项拖入悬浮收集栏，或保持文件管理器当前选择并按快捷键，直接将选中项加入公共收集区，无需先复制。
3. 继续浏览其他文件夹，将需要的文件加入同一收集区。
4. 查看压缩包内部目录预览，处理失效路径、重名等问题，选择保存位置与包名。
5. 按配置的压缩格式统一生成压缩包，查看进度及完成报告。文件传输由用户现有工具完成。

## 一期范围边界

已确认：一期负责本机文件收集与输出，不实现文件传输，实际传输由用户现有工具完成。

一期不包含：云同步、账号、AI 自动找文件、系统右键扩展、多个独立收集篮、加密或分卷压缩、可配置压缩等级、文件夹内部手动排除与自动忽略规则，以及打包后自动删除源文件。可选的文件内容完整性检查留待后续版本，不计入一期；开发验收仍需校验测试文件内容一致。

## 业务规则与异常处理

已确认的快捷键规则：收集目标为触发时系统文件管理器中当前选中的文件或文件夹；支持单选、多选及混选，跨文件夹分次操作均加入同一公共清单。无需用户先复制，剪贴板现有内容不能作为本次收集目标。

已确认的文件夹规则：收集整个文件夹后，打包包含其内容及子目录，保留内部相对目录结构。空文件夹、隐藏项、链接及权限等按下方已批准规则执行。

已确认的输出规则：默认生成压缩包，提供 ZIP、7z、tar.gz 供用户在配置中选择；一期不提供普通文件夹汇总输出。

压缩配置：初始默认 ZIP；用户在设置中修改后保存配置，后续任务及应用重启后沿用。打包对话框可临时切换当前任务格式，不改变全局默认。三种格式均使用内置标准压缩等级，一期不提供等级调节。界面显示格式名称及扩展名，生成真实对应格式的文件，切换格式时同步更新输出扩展名。下方 ZIP64 规则仅针对 ZIP，其他格式分别验证大文件、目录结构及可解压性。

以下业务规则已获批准：

- 快捷键边界：仅读取触发时前台文件管理器的当前选择，不读取其他后台窗口的选择。没有选中文件时提示“请先选中文件”；前台应用不支持、权限不足或无法读取选择时给出明确提示，不误收剪贴板或历史选择。操作后保留文件管理器焦点与选择，便于继续收集。
- 收集内容：接收本地真实文件和文件夹；文本、网页链接、远程文件虚拟占位项不直接作为文件收集。批量输入含不支持项目时，加入支持项并明确提示其余项目。
- 引用方式：仅记录路径，打包时读取当前内容，不保存收集时的内容快照。源文件移动、删除或失去权限时标为不可用。
- 文件夹与子项重叠：同一文件夹和其内部文件同时被收集时，打包去除重复来源，保留它在文件夹内的相对位置；硬链接等不同路径不按内容去重。
- 输出结构：独立文件置于包根目录；文件夹以其名称为根目录。顶层命名冲突按收集顺序追加序号，避免覆盖；同时处理三端解压时的大小写重名与非法名称，变更映射在打包前可查看。
- 特殊文件：一期不跟随符号链接、不递归目录链接；打包前列出此类项目并要求用户移除或明确选择跳过。权限位等系统专属元数据不承诺完整还原；一期目标是普通文件迁移。
- 打包前检查：空清单不能打包；不可用项目需要用户修正或明确选择跳过。输出不得覆盖源文件、静默覆盖已有包或写入待打包文件夹内部。
- 打包期间：同一时间只执行一个打包任务；冻结本次任务的清单、输出路径映射与压缩配置，不复制文件内容快照。允许新项目加入公共清单，并提示用于下次打包；移除或清空公共清单不改变正在执行的任务。取消使用独立入口。源文件被其他程序修改时不提供内容快照一致性保证；读取失败时报告失败项，不将不完整结果当作完整成功。
- 失败与取消：清理本次临时输出，保留源文件及收集清单，允许修正后重新打包；清理失败时提示残留位置。一期不要求断点续打。
- 大文件：采用流式处理，不把全部内容一次载入内存；支持 ZIP64。准备阶段显示扫描状态，正式打包显示进度，失败后说明原因。
- 清单统计：区分顶层条目数和递归文件数；大小扫描中显示计算状态。持久化失败时提示清单尚未保存。
- 隐藏文件：选择整个文件夹时默认包含其隐藏内容；如发现不可读取项目或不支持的类型，按上述规则提示，不静默遗漏。
- 目录预览：只读展示计划输出的包内相对路径与重名映射；清单变化后更新下一任务的预览，正在执行的任务计划不变。打包前重新检查，发现影响输出结构的变化时更新预览并让用户重新确认本次打包。一期按顶层整项管理文件夹，不提供内部手动排除及 .git 等自动忽略规则；问题检查中的明确跳过流程继续保留。
- 问题检查：重复来源按去重规则处理并提示；失效路径、不可读取项目需修正或明确跳过。运行期间新增问题也纳入最终报告。
- 结果报告：以递归普通文件为统计口径，空目录单独统计；展示写入、跳过、失败数量及对应明细，取消或失败任务明确标记未完成。写入临时输出的数量不等于已成功交付的数量。报告本机保留，不自动嵌入共享压缩包。

## 验收标准

已确认核心流程的验收场景：用户先从文件夹 A 选择文件，再从文件夹 B 选择文件，将它们加入同一公共收集区后执行打包，输出结果包含这两次选取的文件。

上述核心流程需要分别在 Linux、Windows 和 macOS 上完成验收。具体测试系统版本及环境待确认。

- 拖拽收集：从不同文件夹分批拖入文件、文件夹或混合项目后，这些项目均进入同一公共收集区，可参与统一打包。
- 快捷键收集：在系统文件管理器中单选、多选或混选文件与文件夹后按快捷键，无需先复制，所有选中项进入同一公共收集区，可参与统一打包。
- 文件夹结构：收集包含多层子目录和文件的文件夹，打包后其内容齐全、内部相对目录结构保持一致；拖拽与快捷键均需覆盖此场景。
- 默认压缩：首次使用且未修改配置时，执行打包生成真实 ZIP 压缩包。
- 输出配置：切换配置中的压缩格式后，下一次打包按该格式生成可解压的压缩包，内容与所选项目一致，扩展名与实际格式相符；对每个支持格式分别验收。
- 选择准确性：剪贴板预先存有其他文件时，快捷键收集结果仍仅来自当前选择；切换文件夹后再次选中文件并收集，原有清单保留且本次选择被追加。

以下验收条目作为一期开发验收依据：

| 场景 | 可观察的预期结果 |
| --- | --- |
| 三目录分批收集 | 拖拽与约定的快捷键均可追加到同一清单，之前收集的项目保留 |
| 清单移除与清空 | 项目从清单消失，磁盘源文件保持原状 |
| 重复添加 | 同一路径只保留一次，用户收到重复提示 |
| 不同来源同名文件 | 两者均进入所选格式的压缩包，按已展示的规则命名，解压后内容分别与源文件一致 |
| 文件夹与子项重叠 | 子项内容只打包一次，所选文件夹的内部相对结构保留 |
| 文件与空文件夹 | 解压后普通文件内容一致，所选文件夹结构及空文件夹存在 |
| 失效路径或权限不足 | 明确列出问题项目，用户修正或选择跳过后才继续；结果说明跳过项 |
| 重启恢复 | 应用重启后恢复清单，失效项以不可用状态显示 |
| 格式配置保存 | 修改压缩格式后重启应用，下次打包仍使用用户选择的格式 |
| 单次格式覆盖 | 默认 ZIP 时，将一次任务改为 7z；本次生成 7z，下次仍默认 ZIP，重启后默认也不变 |
| 保存位置与默认包名 | 首次显示保存对话框；后续默认上次目录、允许修改；默认名称包含日期时间并匹配实际格式；已有同名包不被静默覆盖 |
| 悬浮栏生命周期 | 点击或拖入展开；关闭面板回到小图标；菜单退出结束应用；默认不开机启动，用户可修改设置 |
| 收集不抢焦点 | 在文件管理器选中后按收集键，清单数量更新且有轻提示，文件管理器焦点及选择保持 |
| 任务与清单隔离 | 打包开始后追加、移除或清空公共清单，本次输出仍按已冻结计划执行；新增内容只供下一次任务使用 |
| 文件夹整项管理 | 普通可读取的隐藏项及 .git 等目录默认包含；预览只读，清单可移除整个已收集文件夹，没有子项手动排除入口 |
| 输出冲突 | 已存在目标包不会被静默覆盖，源文件不会被当作输出覆盖 |
| 取消、磁盘不足或读取失败 | 不显示完整成功，不留下被标为成功的半成品包，清单与源文件保留 |
| 大文件 | 对超过 4 GiB 的测试文件生成可解压的 ZIP64 包，解压内容校验一致，界面可响应取消 |
| 快捷键冲突 | 设置失败有明确提示，拖拽及窗口入口仍可用 |
| 未选择或无法读取选择 | 清单不变，提示未选择、不支持或权限问题，不误收剪贴板及历史选择 |
| 目录预览 | 正常完成任务的解压目录与最终预览一致，重名映射一致；变更清单后预览更新 |
| 问题检查 | 注入失效路径、不可读取项目及重复来源后，问题列表能正确指出对应项目，处理或明确跳过后才继续 |
| 结果报告 | 写入、跳过及失败统计与任务实际一致，支持查看明细与改名映射；报告不会自动泄露绝对源路径到包内 |
| 开源构建 | 按 README 在约定的三端环境从源码构建运行，许可证及依赖声明随交付提供 |
| Linux 自编译 | 在声明支持的干净 Linux 环境中，按公开文档安装依赖、编译并运行，核心流程通过验收 |
| CI 交叉编译 | GitHub Actions 按公开工作流执行约定的宿主与目标组合，生成标注目标架构的安装包；在对应目标环境验证安装启动及核心流程 |
| CI 产物追溯 | 下载产物的版本、系统及架构与构建目标一致，可追溯至源码提交；文档提供获取与安装步骤 |
| MIT 交付 | 仓库包含 MIT LICENSE 和明确版权署名，提供第三方依赖声明，构建流程及源码均可公开获取 |

三端测试矩阵需列明系统版本、CPU 架构及实际结果；Linux 还需列明发行版、桌面环境、X11 或 Wayland、文件管理器。不能以某一系统上的结果代替全部平台验收。

## 技术方案与待验证事项

高星仓库参考及已采纳方案见 [一期技术与交付建议](technical-recommendations.md)。当前先完成最小验证原型，再确定正式兼容声明。

1. 原型目标：Windows 11 x64 与资源管理器；macOS 14 起 ARM64/x64 与 Finder；Ubuntu 24.04 x64、GNOME 与 Nautilus。Linux X11 先建立基线，Wayland 需单独验证；不能静默将 Linux 快捷键降级为仅拖拽。

4. 安装产物目标：Windows .exe、macOS 两种架构 .dmg、Linux x64 .deb 与 AppImage。CI 按平台构建，记录实际宿主和目标，版本标签创建草稿 Release。Linux ARM64 真交叉编译需独立原型，不因四目标流水线存在而视为完成。
5. 当前实现与验证结果见 [原型验证记录](prototype-validation.md)。四目标远端 CI、三端真实 IPC 与 Mac 两种 DMG 包内运行已通过；Linux x64 已完成独立 GNOME/X11 会话验证，Windows/macOS 文件管理器完整桌面场景仍待验收。
