# Windows 发布前本机验证记录

日期：2026-10-24。此文记录 1.0.0 发布前先在用户本电脑验证的过程；当时未推送、未发布，也未覆盖已安装的 alpha.13。用户确认后，这些修正才纳入首个稳定版，最终安装包证据见[发布与交互记录](ui-redesign.md)。

## 修正内容

- Windows 默认的无装饰窗口阴影会增加白色非客户区边框、圆角和隐藏偏移。关闭这层原生阴影，由界面绘制自己的圆角；原生窗口尺寸与客户区一致。
- Windows 首次创建窗口时的 DPI / 非客户区协商会使实际内容宽于配置尺寸。窗口创建后重新应用收起状态的客户区约束，保持 104×112 个逻辑像素。
- 弹窗只在实际可见时暂停隐藏。连接弹窗打开后被收起，原先的布尔状态仍为 true，导致悬浮图标一直禁止隐藏；现在收起窗口会释放该暂停状态，重新展开可见弹窗时继续暂停。
- 本机观察到用户把测试窗口拖到了顶部（Y=0）。alpha.13 和最初的本地预览仅检测左右边缘，顶部因此不会隐藏。本轮补齐四边检测、吸附、滑动动画、位置恢复与工作区约束：上下保留 112×10 横条，左右保留 10×112 竖条。多边同时接近时采用距离最近或越界最多的边缘。
- 进一步观察到窗口拖到屏幕底部并部分越界（Y=1542，客户区高 168，工作区底部 1528）。原先用边界距离绝对值判断，会漏掉越过触发带的窗口；现在四边都接受越界，唤回条仍放在可见工作区内。新增四边越界原生检查和该实际坐标的回归断言。

拖到边缘松开后，把鼠标移出窗口约 0.8 秒才会隐藏；鼠标停在窗口上、可见弹窗或打包期间会保持显示。悬停边缘条恢复。测试悬浮框底部显示“本地预览”，便于区别于仍安装的公开版本。

## 本机验证方法

本电脑 Windows，2560×1600 显示器，150% 缩放。使用真实 Tauri/WebView2 窗口和生产贴边线程，原生 API 设置位置并核对实际客户区、外框和工作区坐标；不是浏览器模拟。

```powershell
pnpm build
cargo build --locked --release -p gatherpack --features custom-protocol
./scripts/test-desktop-windows.ps1 -Executable target/release/gatherpack.exe -KeepOpen
```

该显式 CLI 场景使用独立的临时空清单。26 项断言覆盖：首次启动 104×112、外框和客户区一致、四边 10 像素唤回条及工作区可达性、四边部分越界、恢复无尺寸增长、可见弹窗暂停、收起弹窗释放、展开面板在左/上/下隐藏与尺寸恢复。测试窗口标题为“GatherPack · 本地窗口验证”；只有此测试场景启用 Alt+L / Alt+R / Alt+T / Alt+B / Alt+C 定位至左右上下/中间，Alt+S 记录原生状态。

此前左右修复阶段另用 computer-use 实际点击展开、等待隐藏、操作唤回条，确认展开面板由 10×112 恢复至 440×760。本轮四边与越界的 26 项检查使用真实原生窗口 API，并绑定当前程序摘要。当前程序的核心 IPC 31 项、重启恢复 5 项通过；浏览器回归覆盖四方向滑出/恢复动画，以及“收起的弹窗不得继续阻止隐藏”。
