# GatherPack · 第二版 UI 与交互原型

阶段：设计评审。原型使用示例文件，支持浏览器内操作；打包进度、系统定位和连接修复为演示状态，全局快捷键在原型页面内响应。

## 参考与取舍

| 参考 | 借鉴的交互 | GatherPack 的设计 |
| --- | --- | --- |
| [Dropover 官方网站](https://dropoverapp.com/) | 临时浮动收集架、收集后的就地整理 | 小悬浮入口进入轻量收集面板，主要操作集中在手边 |
| [Yoink 开发者在 App Store 的介绍](https://apps.apple.com/us/app/yoink/id457622435?mt=12) | 在不同窗口之间暂存文件的 shelf | 跨文件夹持续收集到一个公共清单，保留来源与计数 |
| [Dropzone 官方网站](https://aptonic.com/) | 收集入口与快捷操作的清晰分工 | 将“收集”与“检查并打包”分层，主界面保持一个主要动作 |

这些产品中的云服务、多收集篮、转换工具和平台专属入口未纳入本轮原型。视觉资产与界面代码为本项目独立绘制和实现。

## 设计方向

- 暖白、雾绿与克制的阴影，提供清楚的前后层次和悬浮感。
- 收起状态可整体拖动；展开状态的宽标题栏可拖动。小幅点击与超过阈值的移动分开处理。
- 清单展示名称、来源、大小和状态，移除后可撤销；同名文件显示自动编号。
- “文件全景”按需展开成宽面板，双向分支展示文件与文件夹。支持展开、选中看路径、缩放、平移和适应画布；保留整项文件夹管理规则。
- 问题集中处理：来源失效支持重新定位或本次跳过；快捷键注册与文件管理器连接分开说明。
- 打包前在同一对话框确认名称、格式、位置和目录。开始后保留可操作的清单，新文件标记为“下次打包”。
- 完成后展示写入、跳过、失败与重名映射，支持定位输出；清单继续保留。
- 手机可直接选择示例文件并点击收集，便于远程评审。

## 查看与生成

源文件：index.html、app.css、app.js。直接用浏览器打开 index.html 即可体验，无需安装依赖。

生成单文件原型、检查截图和演示视频：

    node scripts/design-prototype.mjs --inspect
    node scripts/design-prototype.mjs

生成目录为 artifacts/design/gatherpack-v2。视频生成需要 Playwright 的 FFmpeg 以及可编码 H.264 的 FFmpeg；可通过 FFMPEG_PATH 指定后者。Windows 默认使用 Edge，其他环境使用 Playwright Chromium。

评审重点：悬浮点大小、面板密度、清单与全景的切换方式，以及“先检查、再打包”的步骤是否顺手。
